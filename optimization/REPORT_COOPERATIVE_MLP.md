# Cooperative MLP experiment: rejected

No new serving kernel is selected. The final all-layer screen tests 40 configurations: 32 run and eight are refused before launch because their cluster grids exceed driver-reported residency limits. Every runnable candidate is slower in all six timing rounds. The best is **48.489 µs per chain**, versus **44.519 µs** for the selected path; the median paired regression is **3.977 µs**. These are operator-chain timings, not TTFA.

The prototype combines the selected exact Triton 3.8 gate/up PTX and Triton 3.7 down-projection PTX in one cooperative CUDA kernel, assembled with isolated CUDA 13.0 PTXAS. Original arithmetic, rounding and quantization remain unchanged. Virtual program IDs assign the 384 gate/up and 512 down tiles to 128/256/360/384/480/512 resident CTAs. A release/acquire sense barrier separates writers and readers. Two/four/eight-CTA Hopper cluster variants reduce the number of global barrier participants. All launches check cooperative and cluster residency; ordinary oversubscribed launches are never used for this barrier.

This follows the [CUDA cooperative launch contract](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cooperative-groups.html) and [driver occupancy API](https://docs.nvidia.com/cuda/cuda-driver-api/cuda_driver_api/group__CUDA__OCCUPANCY.html). The original upstream dependency wait and downstream waits remain. A shared counter requires serialized use across ordered CUDA streams; the prototype is benchmark-only.

The measured chain includes gate/up, down, the selected early clustered QKV producer, historical-KV attention, reduction/quantization and register-preloaded output. All 36 real weight sets and three frozen inputs per layer are used, with nearest saved attention metadata and a synthetic last-layer wrap. The final source passes **3,564 intermediate/whole-cache comparisons**, **264 private-graph boundary checks**, and 33 graph-edge inspections. Source changes affected assembler register allocation, so the final comparison reruns all 32 runnable candidates.

Separate post-timing profiles contain 648 control and 540 fused kernel events. Control gate/up/down resident medians are **19.392 / 26.336 µs**, but their joint interval is **27.376 µs** because all 108 pairs overlap, with **18.368 µs median overlap**. The fused MLP takes **30.592 µs**. Resident intervals include dependency waits; they are not useful-work utilization or a latency lower bound.

Memcheck, racecheck and synccheck each pass **315 replay cases** with zero reported errors/hazards/warnings. Seven representative configurations cover changed real/zero/spike inputs, positions, poisoned outputs and entire caches, multiple tiles per CTA, inactive up-stage CTAs, spilling and cluster joins. The reusable counter flips exactly once per replay. These are operator-chain checks using production QKV binaries, not sanitization of every variant or the whole service.

The first three builds fail assembly because a scratch register shadows `%tid.x`; no candidate timing is taken from that attempt. Failed sources, compiler logs, refused configurations and corrected builds remain recorded. No new full-request, HTTP, codec or quality measurement is claimed. All 32 codebooks and streaming voice cloning remain intact; the selected historical-KV preset is unchanged and 50 ms remains unmet.
